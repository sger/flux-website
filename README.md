# Flux website

A static, single-page reference to the [Flux compiler](https://github.com/sger/flux), generated by a small Node script with [Shiki](https://shiki.style/) for build-time highlighting and the Tailwind CSS CLI. No framework and no browser JavaScript.

- `src/page.mjs`: page content (examples, notes, outputs, links)
- `src/components.mjs`: HTML template functions (layout, section, code block, example)
- `src/styles/global.css`: Tailwind entry, theme tokens and dark mode
- `src/data/`: Flux snippets and the vendored grammar
- `scripts/build.mjs`: writes `dist/index.html` and `dist/styles.css`
- `scripts/dev.mjs`: rebuilds on changes and serves `dist/` at `/flux-website/`

## Local development

Use **Node.js 24 LTS** (also recorded in `.nvmrc`) and npm:

```sh
nvm use
npm ci
npm run dev
```

Open the printed local URL under `/flux-website/`.

```sh
npm run build
npm run check:links
```

Production files are generated in `dist/`. `npm run dev` does not live-reload; refresh the browser after a rebuild.

## Content and attribution

The compiler repository is the source of truth; documentation is linked there rather than copied. The page shows short Flux programs, each paired with one factual sentence and its output. Snippets come from upstream commit `6d499c6706b48aa3cd306ad84057b6360b882058` (README and `examples/`); see [`src/data/README.md`](src/data/README.md) for each file's origin and any trimming.

Each snippet was run with a local Flux build (commit `7754b42`) on the VM backend, and the displayed output is its stdout verbatim. The LLVM backend was not exercised. When a snippet changes, run it again:

```sh
flux src/data/<name>.flx
```

The Flux TextMate grammar is vendored for build-time highlighting under the upstream MIT license.

## GitHub Pages

Target: **https://sger.github.io/flux-website/**

`scripts/build.mjs` sets the base path `/flux-website` and the canonical URL `https://sger.github.io/flux-website/`. Local assets use that base; documentation and compiler source references use absolute upstream URLs.

`.github/workflows/pages.yml` builds and checks links on pull requests and main pushes. Only main pushes or a manual workflow run on main can deploy. It uses Node 24, `npm ci`, the Pages artifact, and a deployment job with Pages/OIDC permissions. No existing website workflows were present.

When deployment is requested, the repository's **Settings → Pages → Source** must be set to **GitHub Actions**. No settings have been changed, and nothing has been pushed or deployed by this task. Once pushed to main, the prepared workflow will deploy automatically.

## Validation

`npm run build && npm run check:links` checks fragment targets, local assets, the canonical URL, `/flux-website/` prefixes, and the absence of browser scripts. Layouts were checked in headless Chrome at 375 px and 1280 px, in light and dark mode.
